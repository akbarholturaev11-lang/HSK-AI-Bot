# Android provider checkout stayed pending after browser return

- Sabab: Native Lava checkout checked status once on ON_RESUME. If the webhook arrived later, the visible pending page remained stale. Its separate Material plan/email controls also bypassed the manual checkout's visual/navigation anatomy.
- Fix: Lifecycle-aware refresh checks the same canonical invoice immediately on foreground entry, then every five seconds for at most 15 minutes. Background/terminal status stops polling. The model serializes requests, accepts paid only from an acknowledged status response, and recovers a lost start via canonical pending state. Shared checkout chrome and PWA-derived native limit presentation keep one-step Back and drafts.
- Risk: Redirect/browser return is never purchase proof. Preserve Direct/Play source-set isolation, manual immutable receipts, one-use preview and server pricing/access. A client cannot solve a missing provider webhook by inventing success.
- Prevention: `LavaCheckoutViewModelTest` covers delayed confirmation, invalid/negative replies, duplicate start, pending recovery and offer X behavior. `NativeLavaCheckoutTest` exercises foreground/background polling, shared header, email Back, primary/all plans, loading anchor and UZ/RU/TJ/large text. `SubscriptionCheckoutHostTest` retains manual/HSK30 receipt and stale-result regressions. Dialog windows on Android 15+ must keep the existing full-display inset correction before safe-area padding.

- Native dialog localization: Compose Dialog establishes its own View context. Keep the parent account context/configuration/density inside the limit dialog; otherwise scoped locale or font-scale providers can be replaced by the host default. Neutral-gate tests cover UZ/RU/TJ, 200% text and the always-visible Play support action.

- PWA sequence regression prevention: a manual limit CTA must not open a second tariff picker. Reuse the authenticated selected plan, then show TJ bank / China wallet before requisites as PWA does; More and Back state are owned above provider/manual branches. `SubscriptionCheckoutSequenceTest` and the real host instrumentation cover one quote, the selected tariff/bank and returning to the same parent.
