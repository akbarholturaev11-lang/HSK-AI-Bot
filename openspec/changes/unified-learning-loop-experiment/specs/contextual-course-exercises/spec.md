# Spec Delta

## Purpose
Enable bounded contextual application of verified course material without replacing the source curriculum or creating unsupported claims of learning.

## ADDED Requirements

### Requirement: Accepted experiential need and evidence-aware reuse
The treatment SHALL address the owner's direct qualitative report that lessons feel repetitive. Current source, mechanisms, material coverage and available aggregates SHALL inform reuse, safety and measurement; proof of boredom causality MUST NOT be a prerequisite for designing the new experience. Aggregate limitations MUST remain explicit.

#### Scenario: Existing exercise types are numerous
- **WHEN** the code contains many choice, cloze or builder types but the owner reports experiential sameness
- **THEN** those types are treated as response primitives rather than evidence that the reported product problem is absent
- **AND** design proceeds while analytics distinguishes competing effects and private figures stay outside public project documents

### Requirement: Two experiential application families
The initial treatment SHALL use a coherent two-character voiced scene with a pause and learner role takeover, and a bounded real-life mission requiring independent application, including find/repair variants. Families MUST reuse admitted teaching; translation, missing-turn choices and builders remain response primitives rather than new experiential formats.

#### Scenario: Eligible scene or mission material
- **WHEN** a verified dialogue or taught objective supports a contextual situation
- **THEN** the learner follows coherent character turns and takes a role at a meaningful pause, or completes a bounded practical mission with independent application and optional repair/reapply
- **AND** the chosen response has a verified answer/rubric before delivery; an open spoken response is optional formative practice, not the common assessment grader

### Requirement: Source and locale eligibility
Items MUST retain source identity, Chinese, pinyin and verified UZ/RU/TJ meaning with appropriate reveal timing. Existing source hashes, original keys, official grades, sequence and private-course access SHALL remain authoritative. Supplemental material MUST pass existing agent-owned semantic QA.

#### Scenario: Missing or unsafe material
- **WHEN** content, translation, source revision or unambiguous grading is missing
- **THEN** the existing safe task remains available and a bounded fallback reason is recorded
- **AND** no live generated answer becomes an official key, no unpublished level unlocks, and the learner is not required to review translations

### Requirement: Media and client fallback
The contract SHALL cover all seven currently packaged HSK 2.0/3.0 level keys, three locales and requested learner platforms. Existing picture cards SHALL be reused; audio, microphone, network or unsupported-client failure MUST provide a compatible base/text path without false failure or success.

#### Scenario: Client or media is unavailable
- **WHEN** Android Direct/Play, PWA, Mini App, paired Desktop or legacy bot entry lacks a supported task/media capability
- **THEN** canonical content and progress remain usable through fallback and unsupported delivery is not exposure
- **AND** microphone refusal or unassessed speech is not graded incorrect; picture/voice reuse creates no new provider or entitlement
- **AND** paired Desktop work remains this task's explicit scope exception, not a general unfreeze
