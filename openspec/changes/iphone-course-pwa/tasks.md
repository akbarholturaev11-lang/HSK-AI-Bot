## Acceptance and scope boundary
- Original Telegram Mini App must remain unchanged in behavior.
- Browser-only verified learners must use the **same canonical account services**, not a duplicate dataset.
- Existing account's progress, Pro, history and payment ownership must remain intact.
- Existing account/transactional notices and course/ranking messages remain available in the authenticated inbox and arrive by opt-in PWA push, without changing their existing Android/Telegram delivery.
- Smart PWA transport attaches only to existing consent, capability and one selected job, never a second scheduler or opt-in.
- No Admin PWA identity/subscription reuse, offline sync, new analytics pipeline, new courses, Android/Desktop behavior changes, or major redesign. Add only a migration needed to bind learner push state safely; retain a verified rollback.
- Plan validation (GitHub Actions) confirms only OpenSpec document structure; real runtime/physical iPhone QA is unverified until P3 executes.
